  • 项目描述：从零实现一个工具调用型智能体，覆盖「感知（检索）— 决策（规划）— 执行（工具调用）— 反思（再决策）」的完整闭环，工具通过 MCP 协议独立成 Server 进程，对外以 HTTP + SSE 提供服务。为深入理解机制，核心循环、上下文管理、错误恢复均手写实现而非调用框架，因此具备框架级的问题定位能力。
  • 工具接入（MCP）：按 MCP 协议实现独立 Server 进程，将工具能力以标准协议对外暴露，工具定义与实现只维护一份，本地直调与 MCP 两种接入方式共用——新增工具无需改动 Agent 核心逻辑。基于 stdio 单向传输的特性设计常驻会话适配器，解决跨任务调用导致的 cancel scope 异常。
  • RAG 检索：自建检索链路——按文档语义结构分块（保证条款不被切断、每块带章节标题路径），向量检索与 BM25 混合召回、RRF 融合排序——纯向量对「5000 元」这类数字不敏感，纯 BM25 又抓不住口语化提问，二者互补。针对 12 个不含文档原词的口语化提问，命中率由关键词硬匹配的 58.3% 提升至 100%；检索延迟 6.7ms（numpy 矩阵运算实现，未引入向量数据库）。本地部署 bge 中文向量模型。
  • 调用调度：设计工具路由与参数校验层，处理模型返回的非法参数与幻觉工具名；对无依赖的工具调用做并行执行（asyncio.gather），实测 4 个工具并发下耗时由 805ms 降至 201ms，降低约 75%。
  • 上下文管理：实现两级上下文压缩——长工具结果保留首尾、压缩中段；超出预算时从最老轮次开始裁剪，并保证 tool_use 与 tool_result 始终成对出现（否则 API 直接报 400）。10 轮长文档检索对话下输入 token 由 26999 降至 17972（降低 33.4%），上下文占用由线性增长转为恒定。用量估算：编写 token 估算器并用 API 真实 usage 反推系数校准，误差由 −37% 收敛至 ±1.3%，使预算判断真实可用。
  • 稳定性保障：实现超时控制、指数退避重试与熔断降级三层机制。关键设计是按故障类型选择性重试——超时、连接中断等瞬时故障重试，参数非法、业务拒绝等永久错误立即放弃。在 30% 随机失败 + 5% 超时注入下，工具成功率由 71.7% 提升至 95.8%（+24.1 个百分点），失败减少 85%，代价是下游调用量增加 44%；连续失败自动熔断，避免重试放大下游故障。
  • 服务化与可观测性：FastAPI 提供 HTTP 接口与 SSE 流式输出，实时推送模型正文与工具调用进度；实测首字节响应 231ms、完整回答 2713ms，用户等待时间降低约 91%。会话状态服务端维护并加锁串行化避免历史交错；全链路记录每轮 Thought / Action / Observation，含工具耗时、重试次数与失败原因，支撑成功率统计与问题定位。
